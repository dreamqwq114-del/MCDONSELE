## 3. 真实调用中发现并修掉的 3 个缺陷

这三个都是只有接上真实接口才暴露的，虚构样例测不出来：

1. **`query-nearby-stores` 没带城市/商圈**。`city`、`keyword` 在 schema 里不是 `required`，探针只填必填字段，结果搜出 0 家门店。已改为：schema 里存在的定位类可选字段，有值就补。
2. **菜单是字典不是数组**。`data.meals` 返回 `{商品编码: 商品}` 的映射（112 个键），探针按数组找，报「商品数=0」。已加入字典型列表的摊平逻辑，并把键名补成 `code`。
3. **`calculate-price` 漏传 `items`**。`items` 同样不是 `required`，导致请求只发了门店与类型。已按 `inputSchema` 里数组结构推导出 `productCode` + `quantity` 并补上。
4. **有优惠时把优惠扣两次**。原先取 `productPrice` / `subtotal`（都是**券后**金额）当分账基数，而 `check_plan.py` 又会再减一次 `discount`，导致 `product - discount + fee ≠ total` 被阻断。已改为取 `productOriginalPrice` / `originalSubtotal`（券前）。
5. **套餐不被认定为主食**。真实两件套「龙焰鸡腿堡 + 可乐中杯」明明是 A 的主食，但规则只看 `kind="main"`，判 `MAIN_MISSING` 把方案拦掉。已改为：`combo.confirmed=true` 时，组成里含主食即满足主食需求，含饮料即满足饮料需求。
6. **`price=0` 会被当成免费**。同一商品不带券时接口返回 `price=0`、`productList=[]`，HTTP 200。现在遇到即拒绝出方案。

### 3.1 独立审计后发现并修掉的三个缺陷（19:40）

审计清单离线复现，均确认为真缺陷：

7. **费用由残差反推，校验自证**。原 `fee = total - basis + discount`，使 `basis - discount + fee == total` 恒成立，任何不明差额都会被"证明"成费用并标 `verified`（复现：商品 2000、总额 2300、费用字段全 0 → `fee=300`）。
   现改为：费用只取 `deliveryPrice` / `packingPrice` / `tablewarePrice`，再核对总额；不一致即抛错并报出差额。另加 `券前 - 优惠 == productPrice` 交叉核对。
8. **同款商品多人点会导致行金额翻倍**。聚合数量后把总小计按编码回填给每条行（复现：两人各一份 20 元同款 → 两行各 4000，合计 8000）。
   现改为：`quote()` 返回 `{line_id: 小计}`，聚合小计按数量最大余数拆回；缺行报错，不按 0 元补。
   **真实复验**：两人各点麦香鸡 + 一份可乐，官方 ¥43.50，行金额 1700 / 1700 / 950，合计 4350 分 ✓。
9. **共享名单允许重复成员**。`A+A+B` 被当成三个槽位，A 摊两份且 `feasible=true`。
   现改为：解析阶段拒绝重复成员；核算入口新增 `SHARE_DUPLICATE_MEMBER`（金额层阻断），双保险。

测试数 33 → **43**，新增 `tests/test_live_plan.py`（桩客户端，不联网）。

## 4. 真实数据的形态（对接时必看）

```jsonc
// query-meals → data
{
  "categories": [{"name": "鸡肉汉堡\n/卷", "meals": [{"code": "1406", "tags": ["..."]}]}],
  "meals": {                        // 字典，键 = 商品编码
    "1406": {"name": "板烧鸡腿堡", "currentPrice": "23.5", "originalPrice": "23.5",
             "image": "https://menu-img.mcd.cn/...", "canWithOrder": false}
  }
}

// calculate-price → data
{
  "price": 5850, "productPrice": 5850, "originalPrice": 5850, "discount": 0,
  "productList": [{"productCode": "1406", "productName": "板烧鸡腿堡",
                   "quantity": 1, "originalSubtotal": 2350, "subtotal": 2350}],
  "enjoyable": {"amountType": 3, "realDiscount": 5.0}   // 注意：这里是「元」，不是分
}
```

已确认的单位口径：

- 菜单 `currentPrice` / `originalPrice`：**元**字符串（`"23.5"`），用 `Decimal * 100` 转分。
- `calculate-price` 的 `price` / `productPrice` / `subtotal`：**分**（整数）。
- `enjoyable.realDiscount`：**元**（浮点）。同一响应里混着两种单位，这就是不能"统一除以 100"的实证。
- 分类名里含换行符（`"鸡肉汉堡\n/卷"`），匹配前必须清洗。
