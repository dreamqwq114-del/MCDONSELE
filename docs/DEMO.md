# 演示脚本（3 分钟）

两种模式。**A 已可完整跑通（2026-10-24 实测）**，B 作为离线备案。录屏前先确认自己录的是哪一种，并在画面上保持对应标签不变。

## 模式 A · 真实链路（已验证）

前置：`python scripts/mcd_client.py --ping` 通过，工具数 35。

先把这一单准备好（约 3 秒，可提前跑好避免录屏等待）：

```bash
python scripts/live_plan.py --city 上海 --area 人民广场 --store-code 1450713 \
  --budget A=3000 --budget B=3500 \
  --plan "P1|主食齐全 + 共享脆薯饼|A:main:1406,B:main:1450,B:drink:9900008751,S:A+B:side:521741" \
  --plan "P2|不含共享小食|A:main:1406,B:main:1450,B:drink:9900008751" \
  --out runtime/live-input.json
python scripts/check_plan.py  --in runtime/live-input.json --out runtime/live-result.json
python scripts/render_card.py --in runtime/live-result.json --out runtime/live-card.html
```

| 时长 | 操作 | 预期画面 |
|---|---|---|
| 0:00–0:20 | 只说话，不操作 | 痛点："同桌预算不同，直接 AA 有人超支" |
| 0:20–0:45 | 在 WorkBuddy 输入：两人到店自取，A 最多 30 元、B 最多 35 元，各一份主食，B 必须有饮料，想共享一份小食 | Skill 逐项复述需求，一次问齐缺项 |
| 0:45–1:20 | 给城市 + 商圈 → 从门店列表里**手动选一家** | `query-nearby-stores` 返回 5 家真实门店，选店动作由人完成 |
| 1:20–2:00 | 跑上面的三条命令 | 卡片首屏：门店、核价时间 19:12、总额 ¥58.50、A ¥27.75 / B ¥30.75。徽章为绿色 **"本次实时核价"** |
| 2:00–2:35 | 切到 P2（去掉共享小食） | 总额降到 ¥50.00，A ¥23.50 / B ¥26.50，说明共享小食的真实成本 |
| 2:35–3:00 | 滚动到分摊明细 | 脆薯饼 ¥8.50 各 ¥4.25；分账合计 ¥58.50 = 官方总额 ¥58.50 |

讲解重点：**各自预算被尊重、分账有依据、结果真实可核对**。不要念工具清单。

口播可以这样说："这一单不是算出来的，是麦当劳官方接口报的价——58 块 5，跟我分给两个人的 27.75 加 30.75 一分不差。"

## 模式 B · 虚构样例（离线备案，不需要 Token）

```bash
python scripts/check_plan.py  --in examples/fictional-input.json --out runtime/result.json
python scripts/render_card.py --in runtime/result.json --out runtime/card.html
```

然后打开 `runtime/card.html`。

| 时长 | 操作 | 要点 |
|---|---|---|
| 0:00–0:25 | 讲痛点 | 总价没超但某人超支 / 不吃小食却被均摊 / 套餐里的饮料被重复点 |
| 0:25–0:50 | 展示 `examples/fictional-input.json` | 每人预算、主食、饮料规则、共享意愿、分账规则 |
| 0:50–1:20 | 打开卡片首屏 | **先指出橙色徽章"虚构数据，仅用于功能演示"**，再讲总额与每人应付 |
| 1:20–2:00 | 切到 P2 | 两套方案对比：P1 含共享薯条 ¥61，P2 无小食 ¥47 |
| 2:00–2:35 | 展示"分摊明细" | 共享薯条 11.44 元各 5.72；优惠 −1.41 / −1.59；合计 61.00 = 官方总额 |
| 2:35–3:00 | 讲局限 | 真实 MCP 未连通，这是核算与展示链路的验证；下一步是接 Token 跑真实探针 |

**模式 B 的每一句话都不能说成"实时核价"。** 直接说"这一版验证的是核算与展示，真实报价还没跑通"。

## 真实故障时怎么解释

| 现象 | 怎么说 |
|---|---|
| 401 | "Token 失效了，需要在连接器里更新，不是程序算错。" |
| 429 | "官方限流 600 次/分钟，我降频重试一次。" |
| 工具缺失 | "连接器没连上，看不到菜单工具，现在不能报任何价格。" |
| 套餐核价报错 | "这个套餐官方报价接口不通过，我降级成单品组合。" |
| 卡片显示"分账待确认" | "分账规则没确认或报价没核验，程序拒绝给确定数字，这是设计如此。" |

不要为了画面好看而把上述状态说成成功。评委的评分项里"能跑通"和"真的调用了 MCP"是一票否决项。

## 录屏前检查清单

- [ ] 画面里没有任何 Token、券码、手机号、真实地址
- [ ] 徽章与实际数据来源一致（live 才可说实时核价）
- [ ] 各人应付之和等于总额（口述一遍数字）
- [ ] `workbuddy.md` 与 `docs/DEVELOPMENT_PROVENANCE.md` 能对应上演示内容
